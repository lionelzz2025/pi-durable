## 测试原则

- 用 Node test runner、真实临时 SQLite、faux provider、fake WeChat transport；默认不读取真实凭据、不访问微信、不调用付费模型。
- 每组使用 `data/test-runs/<run-id>/` 并保留产物，不直接删除。进程只停止本测试创建的实例，设置 deadline，不干扰正式服务。
- 对状态/数据/外部调用次数做断言，不以日志文字或模型说“成功”作为证据。
- crash window 用可控 latch/故障注入定位，再硬杀子进程；生产入口不得暴露注入开关。
- 现有命令 `npm run typecheck`、`npm test` 必须通过；新增源码/测试纳入 typecheck。具体新增定向脚本在实施时记录，不能将计划命令写成已经运行。
- Windows 进程间 kill 仅测硬退出；优雅停机用进程内接线与真实 Ctrl-C 人工测试分别报告。
- 所有恢复测试至少验证“新进程 + 同库”，不能只是同进程重建对象。缺少必要运行条件记 blocked，不静默 skip 后宣称全通过。

### 必测 crash window 清单

1. 拉取后、接收事务前；接收事务后、submit 前。
2. submit 后、submissionId 关联前；工具效果 commit 后、工具结果提交前。
3. 模型请求/流式生成中；最终答案 commit 后、outbox 建立前。
4. outbox 建立后、发送前；远端已收、本地未获回执；回执已获、sent commit 前。
5. 提醒到期/取消竞争；迁移中途。

每一窗口记录：持久状态、重启采取的动作、预期业务执行次数/发送次数、未知结果如何暴露。LLM 重试可能再次计费，不将其误写成外部调用 exactly-once。

## 真实微信验收（授权后执行）

前置：用户确认独占账号，主动停止旧 pi 插件；核对进程归属，不抢锁。用户完成 QR；用隔离验收库和唯一前缀，不污染正式待办/记忆。真实模型必须获准并明确预算。测试中不得运行 pi 作为新助手的回复后端。

| ID | 操作 | 必须看到的证据 |
|---|---|---|
| W01 | 冷启动登录，微信提问及创建/完成待办 | 仅独立 daemon 处理；微信回复对应真实 submission/工具结果，库内记录一致 |
| W02 | 先说明一条上下文事实，再退出并重启 daemon；继续指代提问并查待办 | 不补发原消息、不启动 pi，仍同 conversation；能使用历史上下文及原待办，不出现空系统替代 |
| W03 | 明确记住偏好，触发压缩/新会话后重启查询、更正/遗忘 | 新会话仍可检索有效长期记忆；遗忘后不再注入；说明历史审计保留边界 |
| W04 | 接收后和长任务中硬杀进程，再启动 | 自动恢复已接收输入/安全任务；不要求用户重新发；危险副作用不自动重做 |
| W05 | 网络中断/凭据或 token 不可用，再恢复 | 回复有 pending/blocked/unknown 诊断；恢复策略与真实发送次数一致，不能伪造已送达 |
| W06 | 收图片/文件，生成文件并回传，发送超限/不支持附件 | 支持项完整到达且文件 hash 一致；不支持项明确反馈；不能越界读取本机文件 |
| W07 | 建立提醒、停止进程越过到期时间后重启，另取消一个提醒 | 唯一 occurrence，补发一次或真实平台限制 blocked；取消不发送，时区正确 |
| W08 | 取消任务、状态/新会话命令、工具缺失启动守卫、退出及备份恢复 | 控制语义可见；不能悄悄降级为另一套助手；Ctrl-C 排空；恢复后数据一致，无测试连接残留 |

真实平台不支持主动提醒/某媒体时，记录具体限制与诊断，不绕过协议；W 对应项保持 blocked，待用户接受降级范围后才能按该范围验收。模拟网络故障不冒充真实平台故障测试。
